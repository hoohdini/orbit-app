# 수집 데이터와 추천 반영 규칙 (2026-10-05, 개발 지시서 v0.2 B-11, 담당: 민찬)

운영진이 요청한 "미션이 걸리면 데이터가 오염된다"는 우려에 대한 답이다. 원칙은 하나다. 원본은 그대로 쌓고, 추천 계산에 쓸 때만 낮추거나 버린다. 이 문서가 정본이고 숫자는 코드(`services/compute/pipeline/`)와 같아야 한다.

## 운영진용 요약

- 추천과 자리 배정의 기본 재료는 사전 설문 두 문장(지금 하는 일, 오늘 찾는 사람)과 관심 태그다.
- 행사 중 데이터는 커피챗 배정과 자유 이동 추천에만 반영한다. 테이블토크 자리는 전날 확정이라 행사 중 데이터가 바꾸지 않는다.
- 미션 때문에 생기는 포스터 응답은 반영 세기를 낮춘다(미션용 2건은 절반). 명함 교환은 상대가 확인한 것이면 모두 같게 본다(처음 만난 사이에 명찰만 찍고 대화 안 하는 경우는 드물다고 봄).
- 포스터 투표, 한 줄 메모, 퀴즈 시도, 커피챗 만족도는 추천에 쓰지 않는다. 커피챗 만족도는 행사 뒤 평가에만 쓴다.
- 만족도 화면의 사람 고르기(picks)는 리허설 평가의 사람별 정확도(같은 테이블에서 고른 사람의 점수가 안 고른 사람보다 높았나)에도 쓴다(`eval/rehearsal_accuracy.picks_from_satisfaction`).
- 참가자 화면에는 점수, 순위, 궁합 같은 숫자나 표현을 보여 주지 않는다.
- 이용 동의를 거부한 사람(10/5 회의)은 사전 등록 정보로 자리 배정에는 들어가지만, 행사 중 데이터(명함 교환, 만족도, 포스터 응답, 검색어)는 모으지 않는다. 웹 API 가 쓰기 자체를 막으므로(403 CONSENT_REFUSED) 계산 서비스에 들어올 행이 없다. 다른 사람의 추천 · 이름 검색 · 궤도 화면에서도 빠진다.

## 언제 계산에 들어가나

| 계산 | 시각 | 쓰는 신호 | 결과 |
|---|---|---|---|
| 전날 계산 | 설문 마감 뒤 | 사전 설문 | 주소, 이름표 초안, 테이블토크 배정 · 좌석, 전날 추천 목록 |
| 체크인 마감 계산 | 당일 | 사전 설문(현장 등록자만) | 현장 등록자 주소. 배정은 바꾸지 않는다 |
| 커피챗 계산 | 16:45 포스터 응답 마감 뒤 | 사전 설문 + 만족도 + 명함 교환 + 포스터 응답 + 검색어(시제품) | 커피챗 첫 배치 그룹, 그룹 카드 근거 한 줄, 자유 이동 추천 목록 |

포스터 반영이 있는 점수와 없는 점수를 둘 다 저장한다(pair_scores.score 와 score_no_poster). 리허설과 행사 뒤에 포스터 반영이 맞히는 데 도왔는지 비교한다.

## 값을 다시 정하는 법

모든 가중치는 출발값이다. 근거는 연구 저장소 docs/34(가중치 근거 조사)와 docs/35(스피드데이팅 대리 검증)에 있다. 대리 검증에서는 현행 만족도 가중치와 갱신하지 않는 경우가 구분되지 않았다. 그래서 리허설 응답 분포를 보고 다시 정한다. 만족도는 환경변수 `SAT_WEIGHTS` 로 코드 수정 없이 바꿀 수 있다. 포스터 · 명함 값은 `pipeline/signals.py` 상단 상수다.

## 포스터 정보 채우기 (P-03)

발표자 본인 · 같은 소속 응답을 빼려면 posters.presenter_ids 에 발표자의 참가자 id 를, 포스터 벡터를 풍부하게 하려면 summary 에 요약 한 줄을 넣는다. 지금은 적재 스크립트가 없어 SQL 로 넣는다. 비어 있으면 그 필터와 요약은 그냥 건너뛴다.

    update posters set summary = '요약 한 줄', tags = array['키워드1','키워드2','키워드3'],
      presenter_ids = (select array_agg(id) from participants where event_id = 'orbit-2026' and display_name in ('발표자1','발표자2'))
    where code = 'P01';

동명이인이 있으면 이름 대신 id 를 직접 넣는다. '연세대 응용통계'처럼 넓은 소속이면 많은 응답이 빠질 수 있어 커피챗 계산 결과의 poster_filter.same_affiliation 수를 리허설에서 본다.

## 이미 아는 사이 (10/5)

추천 목록(B-06)에서 크게 감점하고 탐색 칸에도 넣지 않는다. 판정은 `pipeline/people.py`.

- 같은 기수이면서 같은 소속
- 같은 활동팀(프로젝트 · 스터디)을 한 적 있음. 명단 CSV '활동팀' 열(; 로 구분) → participants.teams
- 소속은 글자를 맞춘 뒤 비교한다: 띄어쓰기 · 문장부호 · 대소문자 · 전각 무시, '대학교' → '대', 단어 끝 학과 · 학부 · 전공 · 과 · 부와 끝의 '학'을 지움. '연세대학교 산업공학과' = '연세대 산업공학'. 영문 · 약어(Yonsei, YU)는 못 맞춘다 → 사전 등록 폼에서 소속을 고르게 하는 것이 근본 해결
- 포스터 응답의 '발표자와 같은 소속' 판정도 같은 맞춘 소속을 쓴다
