# 행사 당일 계산 운영 가이드 (2026-09-29, 담당: 성하)

행사 전날과 당일에 운영자가 계산을 돌리고 배정을 공개하는 순서다. 계산 서비스는 운영자 노트북에서 띄운다(9/29 결정).

## 왜 배포 주소의 콘솔에서는 계산 버튼이 안 되는가

계산 버튼은 웹 서버가 COMPUTE_URL 로 계산 서비스를 부른다. 배포 주소(vercel.app)의 웹 서버는 Vercel 에 있으므로 COMPUTE_URL 이 http://localhost:8000 이면 Vercel 자기 자신을 가리키고, 운영자 노트북에는 닿지 않는다. 그래서 곧바로 연결 오류가 난다(9/29 기록: 0.045초 만에 실패).

해결은 둘 중 하나다.

1. 기본: 운영자 노트북에서 웹도 같이 띄우고 http://localhost:3000/ops 로 들어가 버튼을 누른다. 노트북 웹 서버가 노트북 계산 서비스를 부르니 닿는다. 결과는 같은 DB 에 쓰이므로 참가자는 배포 주소에서 그대로 본다.
2. 예비: 콘솔 상태판 아래의 curl 명령을 노트북 터미널에서 직접 부른다. 결과는 1과 같다.

배포 주소의 콘솔은 체크인 관리, 배정 확인과 공개, 이름표, 포스터 현황처럼 계산이 아닌 기능에 그대로 써도 된다.

## 운영자 역할 나누기 (9/29 결정: 1번 방식)

| 누가 | 어디서 | 무엇을 |
|---|---|---|
| 성하 | 노트북 http://localhost:3000/ops | 계산 돌리기 세 가지. 필요하면 공개도 |
| 성하(폰) | 같은 와이파이에서 http://<맥 IP>:3000/ops | 노트북을 떠나 있을 때 계산 돌리기 |
| 다른 운영자 4명 | 폰으로 배포 주소 /ops | 체크인 관리, 배정 확인과 공개, 포스터 현황과 추첨 |
| 참가자 | 폰으로 배포 주소 | 참가자 기능 전부 |

계산 결과는 같은 DB 에 쓰이므로 노트북에서 계산하면 폰의 콘솔과 참가자 화면에 바로 보인다. 맥 IP 는 시스템 설정의 와이파이 세부사항에서 본다. 이 주소는 http 라 폰 카메라가 열리지 않지만 콘솔에는 카메라가 필요 없다.

## 행사 전 준비 (리허설 때 한 번 끝까지 해 본다)

0. DB 에 마이그레이션 0008 · 0009 · 0019 가 들어가 있는지 본다. 없으면 웹 · 계산 서비스가 칸이 없다는 오류를 낸다(docs/SETUP_SUPABASE.md 6). 0019(일찍 나감)는 없어도 화면은 돌지만 일찍 나가요 · 나감 표시가 503 으로 실패하므로 행사 전에 넣는다.

1. 노트북 두 곳의 설정이 배포와 같은 행사를 가리키는지 본다.
   - apps/web/.env.local 과 Vercel 환경변수: SUPABASE_URL 이 같은 프로젝트, EVENT_ID 가 같은 값(실제 행사는 orbit-2026)
   - services/compute/.env: SUPABASE_URL, SUPABASE_SERVICE_ROLE_KEY 가 같은 프로젝트, COMPUTE_SECRET 이 apps/web/.env.local 의 값과 같다
2. 참가자 명단을 적재한다. 운영자 11명(모델링팀 5 + 15기 운영진, 박성하 겹침)은 OPERATORS 명단으로 is_admin 이 자동으로 켜진다(docs/OPERATORS.md).
   python scripts/import_participants.py 명단.csv --event-id orbit-2026 --pin-out 저장소밖/pins.csv --fixed-names 저장소밖/table1.txt --exclude "배소윤,박현진"
   - table1.txt 에 1번 테이블(운영진 7 + 연사 교수 3 = 10명) 이름을 줄마다 적는다. 출력의 '1번 테이블 고정 10명' 과 CSV 에 없는 이름 줄이 없는지 본다(10/21 민찬 결정). 먼저 --dry-run 으로 본다
3. 노트북 전원 어댑터, 절전 끄기(시스템 설정의 잠자기 안 함), 행사장 와이파이 접속을 확인한다. 노트북이 잠들면 계산 서비스도 멈춘다.

## 노트북에서 띄우기 (전날과 당일 매번)

터미널 두 개를 연다.

터미널 1, 계산 서비스:

    cd ~/orbit-app/services/compute
    set -a; . ./.env; set +a
    .venv/bin/uvicorn main:app --port 8000

터미널 2, 웹(운영 콘솔용):

    cd ~/orbit-app/apps/web
    npm run dev

브라우저에서 http://localhost:3000/ops 에 박성하 계정으로 로그인한다. 계산 서비스 칸이 연결됨으로 나오면 준비가 끝난 것이다. 모델 올라가 있음이 아니어도 괜찮다. 첫 계산 때 모델을 올리는 데 10초 정도 걸린다.

연결 안 됨이 나오면 터미널 1이 켜져 있는지, http://localhost:8000/health 가 열리는지 본다.

## 전날 (설문 마감 뒤)

1. 계산 서비스 칸에서 전날 계산의 돌리기를 한 번 누른다. 새 코드북과 전원 주소, 테이블토크 배정 초안이 생긴다.
   - 다시 누르면 전원의 주소가 바뀐다. 이름표를 고치기 전이 아니면 다시 누르지 않는다.
2. 이름표 칸에서 첫자리 묶음마다 붙은 초안 이름을 고친다. 고친 이름표는 이후 계산이 덮어쓰지 않는다.
3. 배정 버전 칸에서 테이블토크 초안의 배정 보기로 테이블 구성과 사람별 이유를 훑고 공개한다. 테이블토크는 전날 확정이고 당일 다시 배정하지 않는다(개발 지시서 v0.2 결정 3). 행사장은 10테이블이다. 1번은 교수 · 운영진석(운영진 7 + 연사 교수 3 = 10명, 명단 적재 때 --fixed-names 로 정함), 2~10번에 나머지가 고르게 앉고 좌석 번호까지 정해진다.

> **주의(접두사 끝 공백 수정, 10/9)**: `EMBED_PREFIX` 끝 공백을 늘 하나로 맞추는 `clean_prefix` 수정이 배포되기 전에 이 행사의 전날 계산(코드북 · `sids.offer_vec`/`seek_vec`)을 `set -a; . ./.env` 방식으로 이미 돌렸다면, 그 벡터는 끝 공백이 없는 접두사로 만들어졌을 수 있다. 체크인 마감 계산(`reuse_codebook=true`)은 저장된 코드북을 그대로 쓰므로, 고치지 않고 그대로 이어가면 새 벡터(끝 공백 있음)와 섞여 주소 · 점수가 틀어진다. 이 수정이 배포된 뒤 행사 전에 전날 계산(`reuse_codebook=false`)을 한 번 더 돌린다. 이미 운영자가 고친 첫자리 묶음 이름표는 새 코드북 버전으로 넘어오지 않으니 다시 고쳐야 한다.

## 당일

### 체크인 (입장 ~ 체크인 마감)

1. 참가자는 입장 QR 로 들어와 첫 로그인하면 자동으로 체크인된다.
2. 폰이 안 되는 사람은 체크인 칸에서 이름으로 찾아 수동 체크인한다. 명단에 없는 사람은 워크인 추가, 숫자를 잊은 사람은 숫자 재발급.
3. 상태판에서 체크인 수를 보며 마감 시각을 정한다.

### 체크인 마감 직후: 현장 등록자 주소

1. 체크인 마감 계산의 돌리기를 누른다. 전날 코드북을 그대로 쓰고 현장 등록자에게만 주소를 붙인다. 새 배정 초안은 생기지 않는다.
2. 현장 등록자의 테이블 · 좌석은 체크인 칸의 워크인 추가에서 정한다(v0.2 A-05, 인원이 가장 적은 테이블 끝 좌석). 오지 않은 사람의 자리는 빈자리로 둔다.
   - 2026-10-05 기준 A-05 는 아직 없다. 그 전까지는 운영진이 빈자리로 안내하고, 현장 등록자는 커피챗부터 서비스 배정에 들어간다(커피챗은 체크인 기준).
3. 현장 등록자가 더 오면 같은 순서를 다시 한다. 이미 주소가 있는 사람은 그대로다.

### 테이블토크 동안

상태판에서 만족도 응답률을 본다. 응답률이 50% 미만이면 커피챗 계산이 만남 반영을 끄고 텍스트 점수로만 배정한다(결과에 만남 반영 끔 표시). 진행자에게 만족도 응답을 한 번 더 안내해 달라고 한다.

### 포스터세션 중: 커피챗 배정

0. 커피챗 시각에 맞춰 늦게 오는 사람이 있으면(운영진이 미리 들은 경우), 커피챗 계산 전에 체크인 칸에서 그 사람을 이름으로 찾아 지연 체크인으로 표시를 켜고 수동 체크인한다(10/23 운영진).
   - 커피챗 계산은 체크인한 사람만 앉히므로, 이렇게 해 두면 그 사람도 테이블 · 좌석을 받고 도착할 때까지 그 자리를 비워 둔다. 도착해서 첫 로그인해도 체크인은 그대로다.
   - 지연 체크인한 사람은 주도 선배로 뽑지 않는다(구현하며 정함: 선배가 늦으면 테이블을 이끌 사람이 없다). 결과의 late_checkins 로 몇 명이 지연 체크인인지 본다.
   - 이미 체크인한 사람은 표시를 바꿀 수 없다(수동 체크인이 이미 됨으로 끝난다). 이미 와 있는 사람이므로 할 일이 없다.
   - 일찍 나가는 사람(10/25 민찬 결정): 커피챗 계산 전에 진행자가 한 번 안내한다. 안내 문구 예: 커피챗 전에 가시는 분은 마이 탭의 일찍 나가요를 눌러 주세요. 커피챗 자리를 배정하지 않습니다.
     - 본인이 누르면 체크인 칸 체크인 열에 회색으로 나감 hh:mm(본인)이 뜨고, 상태판 체크인 칸 아래와 체크인 칸 위 숫자(체크인 n · 나감 m)에 센다.
     - 폰을 못 쓰거나 운영진에게 말로 알린 사람은 체크인 칸에서 이름으로 찾아 나감 표시를 누른다(나감 hh:mm(운영자)). 잘못 눌렀거나 다시 오면 같은 자리의 되돌리기를 누른다. 본인도 마이 탭의 다시 참여할게요로 되돌릴 수 있다.
     - 커피챗 계산은 나감 표시한 사람을 앉히지 않고 주도 선배로도 뽑지 않는다. 결과의 left 가 뺀 사람 수다.
     - 말없이 나간 사람은 알 수 없다. 그 사람 자리는 비어 있게 된다.
1. 포스터세션 끝 무렵에 커피챗 계산의 돌리기를 누른다. 늦게 누를수록 포스터 관심도가 더 많이 반영된다. 여러 번 눌러도 된다.
2. 결과 칸에서 만족도 응답률, 만남 반영 끔 여부, 이미 만난 사람끼리 같은 테이블(forbid_hits, 본행사 규모에서는 보통 0), 주도 선배 수(leads, 보통 20)를 본다.
   - forbid_hits 읽는 법: 리허설처럼 인원이 적으면 테이블이 작아 주도 선배 비중이 커지고 0 이 아닐 수 있다(검토 때 가상 6 · 9 · 14명에서 9 · 8 · 3쌍). 본행사에서도 테이블토크 한 테이블이 11명 이상이면(1번 고정 테이블 포함) 10테이블에 나눠도 둘은 같은 테이블이 되므로 피할 수 없는 재회가 생긴다. 이 두 경우가 아닌데 0 이 아니면 계산 담당에게 알린다.
3. 배정 버전 칸에서 커피챗 초안을 배정 보기로 확인하고 공개한다. 커피챗은 1번 고정 없이 체크인한 전원(운영진 · 교수 포함)이 1~10번 테이블에 고르게 앉는다(10/22 민찬 결정). 테이블마다 '주도' 표시가 붙은 두 명이 주도 선배다(기수가 높은 선배 중 분야가 맞는 둘). 주도 선배를 자리 바꾸기로 옮기면 주도 표시는 그 사람을 따라간다(옮긴 테이블의 주도 선배 수가 바뀌므로 선배는 선배끼리 바꾼다).
   - 테이블마다 좌석 번호가 있다(테이블토크와 같이 이웃끼리 잘 맞는 순서, 10/23). 주도 선배 둘은 마주 보게 앉는다(8명 테이블이면 1번 · 5번 좌석, 10/23 운영진 확정). 참가자 화면 · 상태 띠에 n번 테이블 m번 자리로 보이고, 인쇄 좌석표(커피챗)에도 좌석 칸이 찍힌다.
4. 커피챗 공개 뒤에 처음 온 사람(10/25 민찬 결정): 첫 로그인 · 수동 체크인 · 워크인 추가 때 공개된 커피챗에 자리가 저절로 생긴다. 운영진이 할 일은 의자 하나를 더 놓는 것뿐이다.
   - 어디에 앉는지: 체크인 칸의 체크인 열에 주황색으로 늦게 와서 커피챗 n번 테이블 m번 자리가 뜬다(수동 체크인 · 워크인 추가 직후 알림에도 같은 문구). 배정 보기에서는 그 사람 옆에 늦게 옴 · 의자 추가 표시가 붙는다. 그 테이블에 의자를 하나 더 놓고 안내한다. 본인 화면에도 같은 테이블 · 자리가 바로 보인다.
   - 고르는 법: 행사 전 프로필로 잘 맞는 테이블. 인원이 가장 적은 테이블보다 2명 이상 많은 테이블과 같은 기수가 이미 3명인 테이블은 되도록 피한다. 좌석 번호는 그 테이블의 마지막 번호 다음이라 앉아 있는 사람 번호는 바뀌지 않는다.
   - 표시에 (인원이 가장 적은 테이블)이 붙으면 계산 서비스가 2.5초 안에 답하지 못했거나 프로필이 비어 있어 인원이 가장 적은 테이블로 앉힌 것이다. 자리는 그대로 써도 된다.
   - 커피챗 계산 뒤 · 공개 전에 들어온 사람은 공개 뒤 본인 화면이 다음 상태를 읽을 때(15초 안) 자리가 생긴다. 체크인 칸은 30초마다 새로 읽는다.
   - 마무리 · 시상 단계로 넘긴 뒤나 행사 직후 추천(final)을 공개한 뒤에는 자리를 만들지 않는다.
   - 늦게 온 사람은 그 커피챗 버전의 추천 목록 · 그룹 근거 한 줄이 없다(계산 때 없었다). 커피챗 계산을 다시 돌려 공개하면 전원이 새로 앉으므로 커피챗 중에는 다시 돌리지 않는다.
5. 커피챗 계산 뒤에 나감 표시한 사람(10/25 민찬 결정): 배정 보기에서 그 사람 옆에 나감 · 빈자리 표시가 붙고, 지표 칸 체크인 안 한 사람 · 나감에 센다.
   - 공개 전이면 계산을 한 번 더 돌려 새 초안을 공개해도 된다(그 사람이 빠진다). 그냥 공개하면 그 자리는 비어 있다.
   - 공개 뒤면 자리를 그대로 둔다(다시 계산하지 않는다. 빈자리). 그 테이블은 늦게 온 사람 자리를 고를 때 인원이 적은 테이블로 센다.
   - 계산 전에 나감 표시했다가 되돌린 사람은 공개 뒤 본인 화면이 다음 상태를 읽을 때 늦게 온 사람처럼 자리를 받는다(의자 하나 추가).
   - 마무리 단계부터는 참가자 화면에서 일찍 나가요가 사라진다. 행사 직후 추천(final)은 나감 표시와 상관없이 전원에게 추천을 만든다.

### 포스터세션 뒤: 추첨

포스터 칸에서 포스터별 스탬프와 응모권 수를 보고 추첨한다. 응모권 1장이 1표이고 한 사람은 한 번만 뽑힌다.

### 마무리 · 시상: 행사 후기와 특별 시상 순위

마무리(wrapup)로 넘기면 미션이 마감되고 행사 후기만 열린다(10/22 민찬 결정). 진행자는 "이벤트 탭에서 행사 후기를 남기면 스탬프 1칸"이라고 안내한다. 후기는 시상 · 추첨(award) 단계까지 받으므로, 순위는 후기를 받은 뒤 콘솔 이벤트 · 미션 칸의 특별 시상 후보 표에서 본다.

특별 시상 순위 규칙(10/23 민찬 결정, 공개 규칙). 위 줄부터 비교하고 같으면 다음 줄로 넘어간다. 서두르게 만들지 않도록 시각(먼저 모은 사람)은 보지 않는다.

| 순서 | 기준 | 콘솔 표 칸 |
|---|---|---|
| 1 | 스탬프 수 많은 순. 0~5칸(포스터 관심도 1 · 퀴즈 1 · 명함 교환 3명 1 · 5명 1 · 행사 후기 1) | 스탬프 |
| 2 | 추천 인물과의 교환 수 많은 순. 추천 인물은 교환하기 전에 내 오늘 만나면 좋을 분 목록에 떴던 사람이다. 서로 다른 사람만, 5명까지 센다 | 추천 인물 교환(최대 5) |
| 3 | 유효 포스터 응답 수 많은 순. 5초 이상 걸려 낸 응답만 센다 | 포스터 |
| 4 | 셋이 모두 같으면 공동 순위(같은 순위 번호, 표에 공동 n위) | 순위 |

예시: A · B 모두 5칸이다. 추천 인물 교환은 A 7명 → 5명까지만 세서 5, B 5 로 동점이다. 포스터는 A 4 · B 6 이므로 B 가 앞선다. B 1위, A 2위다.

- 마무리로 넘긴 시각 뒤의 포스터 · 퀴즈 · 명함 교환은 세지 않는다. 후기만 마감 뒤에 받는다.
- 제외 명단(현장 운영진, 모델링팀)에 올린 사람, 스탬프가 0칸인 사람, 이용 동의(개인정보 수집)를 거부한 사람은 후보에 나오지 않는다. 동의했다가 나중에 거부한 사람도 그 전 기록과 상관없이 뺀다. 명함 공개만 거부한 사람은 후보에 남는다. 거부자는 후기를 낼 수 없다(10/23 민찬 결정).
- 표는 20위까지 보인다. 20위가 공동이면 공동인 사람을 모두 보인다. 공동 순위 안의 줄 순서는 이름 순이고 순위와 상관없다.
- 공동 순위 때문에 상 개수보다 받을 사람이 많아지는 경우의 처리는 아직 정하지 않았다(운영진 확인 필요). 앱은 순위를 더 가르지 않는다.

참가자 안내 문구(진행자가 미션 시작 때 읽는다):

> 특별 시상은 스탬프를 많이 모은 순서로 정합니다. 스탬프가 같으면 오늘 만나면 좋을 분 목록에 뜬 분과 명함을 많이 교환한 순서(5명까지), 그다음은 포스터에 5초 이상 생각하고 답한 수로 정합니다. 먼저 모은 순서는 보지 않으니 서두르지 않으셔도 됩니다.

### 시상 · 폐회 뒤: 행사 직후 추천

행사 뒤 연락용 추천 목록을 한 번 더 만든다. 커피챗 그룹은 그대로 두고 추천만 바뀐다(오늘 동석했거나 명함을 교환한 사람은 빠진다).

1. 콘솔 버튼이 아직 없다. 노트북 터미널에서 부른다(먼저 `set -a; . services/compute/.env; set +a`).
   ```
   curl -X POST http://localhost:8000/coffeechat -H "X-Compute-Secret: $COMPUTE_SECRET" -H "Content-Type: application/json" -d '{"event_id":"<행사 id>","final":true}'
   ```
2. 결과의 late 는 커피챗 자리 없이 체크인한 사람 수다. 이 사람들은 조 번호 없이 추천만 받는다. 커피챗 공개 뒤 늦게 와서 자리를 받은 사람(10/25)은 원본 자리 그대로 들어가므로 late 에 세지 않는다.
3. 배정 버전 칸에서 새 커피챗 초안(params.kind=final)을 공개한다. 공개하면 원래 커피챗 버전은 retired 가 되고 화면은 이 버전을 읽는다. 그룹 · 조 번호는 같다.
   지금 화면은 버전이 바뀌면 네트워킹 탭에 '새 테이블이 배정됐어요' 카드를 다시 띄운다(조 번호는 같음). 공개 전에 단톡방에 '행사 뒤 추천이 새로 떴다, 조 이동 아님'을 알린다.
4. 되돌릴 때: final 을 철회하고 바로 다시 부른 뒤 바로 공개한다. 원래 커피챗 그룹을 다시 찾아 같은 그룹으로 새 초안을 만든다. retired 가 된 원래 버전은 다시 공개할 수 없어서, 철회와 새 공개 사이에는 커피챗 화면과 커피챗 추천이 비어 있다.

## 문제가 생겼을 때

| 증상 | 할 일 |
|---|---|
| 계산 버튼이 연결 오류 | 배포 주소가 아니라 localhost:3000/ops 에서 눌렀는지 본다. 터미널 1이 꺼졌으면 다시 띄운다 |
| 비밀키가 맞지 않는다 | services/compute/.env 와 apps/web/.env.local 의 COMPUTE_SECRET 을 맞추고 둘 다 다시 띄운다 |
| 55초 안에 끝나지 않았다 | 계산 서비스 터미널에 끝났다는 줄이 찍혔는지 본다. 끝났으면 배정 버전 칸을 새로 고치면 초안이 있다. 안 끝났으면 다시 누른다 |
| 계산 서비스가 거절했다 | 메시지를 그대로 읽는다. 저장된 코드북이 없다면 전날 계산을 먼저, 사람이 부족하다면 체크인 수를 본다 |
| 웹을 띄울 수 없다 | 상태판 아래 curl 명령을 터미널에서 순서대로 부른다. 먼저 set -a; . services/compute/.env; set +a 로 COMPUTE_SECRET 을 올린다 |
| 잘못된 배정을 공개했다 | 배정 버전 칸에서 공개 철회를 누르고, 맞는 초안을 다시 공개한다. 철회만 하면 참가자 화면에서 배정이 사라진다 |
| 운영자가 콘솔에 못 들어온다 | is_admin 이 켜졌는지 체크인 칸의 운영자 표시로 보고, 켰다면 그 사람이 로그아웃 뒤 다시 로그인한다 |
