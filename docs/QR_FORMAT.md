# QR 문자열 형식 (2026-09-25)

QR 은 세 종류다. 공용 스캐너가 앞자리로 구분한다. 내장 카메라로 찍어도 동작해야 하는 것은 URL 로 만든다.

| 종류 | 누가 만드나 | 문자열 | 내장 카메라로 찍으면 | 앱 스캐너로 찍으면 |
|---|---|---|---|---|
| 입장 | 운영진이 입구에 인쇄(공용 1개) | `https://<앱주소>/onboarding` | 앱이 열리고 이름과 숫자 4자리 입력 화면. 입력하면 바로 로그인된다 | 쓰지 않음 |
| 명함 | 명찰에 인쇄(`scripts/export_badge_qr.py`). 앱의 내 명함 화면에도 같은 것이 뜬다 | `https://<앱주소>/card?p=<participant_id>` | 앱이 열리고 교환 결과 화면(로그인 필요. 로그인 뒤 제자리로 돌아온다) | `/api/card/scan` 호출 |
| 포스터 | 운영진이 포스터마다 인쇄(`scripts/export_poster_qr.py`) | `https://<앱주소>/poster?c=<poster_code>` | 앱이 열리고 퀴즈 화면(로그인 필요) | `/api/poster/scan` 호출 |

## 규칙

1. 세 종류 모두 URL 이다. 내장 카메라와 앱 스캐너 둘 다 같은 문자열을 처리한다(회의록 14 의 리서치 항목을 이 형식으로 닫는다).
2. 구분은 경로(`/onboarding`, `/card`, `/poster`)로 한다. 스캐너 컴포넌트는 URL 을 파싱해 경로에 따라 모듈 API 로 넘긴다.
3. `participant_id` 는 uuid 다. 명함 QR 에 이름이나 연락처를 넣지 않는다. 명찰에 인쇄하므로 적재를 다시 해도 id 가 바뀌지 않아야 한다(적재 스크립트가 이름·소속으로 기존 사람을 찾아 갱신한다).
4. 명함 QR 은 한쪽만 찍어도 양방향으로 교환된다. 찍힌 사람의 화면에 "OO 님에게 명함이 공유되었습니다" 가 뜬다.
5. 입장 QR 은 개인별이 아니라 공용이다. 신원은 이름과 사전에 정해 둔 숫자 4자리(휴대폰 뒤 4자리 또는 무작위)로 확인한다(개인별 토큰 `entry_token` 은 예비 컬럼으로만 남긴다).
6. 인식 실패, 형식 불일치, 같은 사람 반복 스캔(60초 안)은 화면에서 안내하고 `event_log` 에 `scan_fail` 로 남긴다.

## 스캐너 라이브러리

`html5-qrcode` 를 쓴다. HTTPS 에서만 카메라가 열리므로 로컬 개발은 `localhost` 로, 폰 테스트는 Vercel 배포 주소로 한다. 카메라 권한 거부 시 수동 입력 칸(포스터 코드 또는 상대 이름 검색)을 둔다.
