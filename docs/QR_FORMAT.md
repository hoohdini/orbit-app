# QR 문자열 형식 (2026-09-25)

QR 은 세 종류다. 공용 스캐너가 앞자리로 구분한다. 내장 카메라로 찍어도 동작해야 하는 것은 URL 로 만든다.

| 종류 | 누가 만드나 | 문자열 | 내장 카메라로 찍으면 | 앱 스캐너로 찍으면 |
|---|---|---|---|---|
| 입장 | 운영진이 사전 등록자마다 발급(이메일·카톡) | `https://<앱주소>/onboarding?t=<entry_token>` | 앱이 열리고 토큰으로 로그인 화면 | 쓰지 않음 |
| 명함 | 앱이 내 명함 화면에 표시 | `https://<앱주소>/card?p=<participant_id>` | 앱이 열리고 상대 명함 저장 화면(로그인 필요) | `/api/card/scan` 호출 |
| 포스터 | 운영진이 포스터마다 인쇄 | `https://<앱주소>/poster?c=<poster_code>` | 앱이 열리고 퀴즈 화면(로그인 필요) | `/api/poster/scan` 호출 |

## 규칙

1. 세 종류 모두 URL 이다. 내장 카메라와 앱 스캐너 둘 다 같은 문자열을 처리한다(회의록 14 의 리서치 항목을 이 형식으로 닫는다).
2. 구분은 경로(`/onboarding`, `/card`, `/poster`)로 한다. 스캐너 컴포넌트는 URL 을 파싱해 경로에 따라 모듈 API 로 넘긴다.
3. `participant_id` 는 uuid 다. 명함 QR 에 이름이나 연락처를 넣지 않는다.
4. `entry_token` 은 임의 문자열이다. 로그인 뒤에는 쓰지 않는다.
5. 인식 실패, 형식 불일치, 같은 사람 반복 스캔(60초 안)은 화면에서 안내하고 `event_log` 에 `scan_fail` 로 남긴다.

## 스캐너 라이브러리

`html5-qrcode` 를 쓴다. HTTPS 에서만 카메라가 열리므로 로컬 개발은 `localhost` 로, 폰 테스트는 Vercel 배포 주소로 한다. 카메라 권한 거부 시 수동 입력 칸(포스터 코드 또는 상대 이름 검색)을 둔다.
